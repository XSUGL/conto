# conto

Сколько стоит работа модели, куда именно уходят деньги и что с этим
делать. Каждый совет посчитан по журналу вызовов, а не взят из головы.

## Что показывает

```
Запросов:        120, из них из кэша 75 (63%)
Потрачено:       $0.568
Кэш сберёг:      $0.961  (63% от того, что было бы)

Модель                вызовов      вход     выход      деньги   доля
claude-opus-5             33     34198     11791     $0.466   82%
claude-sonnet-5           12     12439      4351     $0.103   18%

Что видно по журналу:
  · Общая инструкция в 1019 токенов оплачивается в каждом запросе.
    Кэш префикса дал бы $0.175 (31% счёта).
  · Выход стоит $0.360 против $0.208 за вход:
    дело в длине ответов, а не в размере промпта.
  · Половина потока claude-opus-5 на claude-haiku-4-5 дала бы $0.186.
    Но только если качество это выдержит: мерить до, а не после.
```

Ни один из этих советов не общий. У каждого есть сумма, посчитанная
на конкретном журнале, и её можно проверить.

## Три решения

**Неизвестная цена это не ноль.** Модель, которой нет в `prices.json`,
не прибавляет к счёту нулей молча: её вызовы считаются отдельно и
называются в отчёте. Иначе отчёт был бы тем ниже, чем больше в потоке
незнакомых моделей, то есть врал бы в самую удобную сторону.

**Цены лежат файлом с датой, а не в коде.** Они меняются, а отчёт,
посчитанный по забытой цифре, врёт тише и опаснее, чем отчёт, который
не посчитался вовсе. Дата обновления печатается под каждым отчётом.

**Ключ кэша включает настройки, а не только текст.** Один и тот же
вопрос при другой температуре или другом усилии это другой запрос,
и складывать их в одну ячейку значит подменять ответ.

## Кэш

Кэш здесь не про будущее, а про то, что уже происходит: конвейеры
перезапускают. Правишь промпт, падает прогон на середине, гоняешь
заново тот же список. На стенде это три прогона по сорока сайтам,
из которых у части в третий раз обновились данные:

```
node replay.mjs             # 120 запросов, кэш включён   $0.568
node replay.mjs --no-cache  # те же 120 без кэша          $1.53
node report.mjs run-cached.json run-plain.json
```

Разница 63%, и это не оптимизация, а просто неоплачивание того, что
уже оплачено.

## Настоящей модели не нужно

Стенд меряет не модель, а конвейер: сколько он делает вызовов, сколько
из них повторные и во что это обходится. Поэтому вызов подделан,
а токены считаются по длине. Чтобы померить свой поток, оберните
настоящий вызов:

```js
import { createMeter } from "./meter.mjs";
const meter = createMeter();

const res = await meter.run(
  { model: "claude-opus-5", system: SYSTEM, prompt, tag: "судья" },
  async (req) => {
    const r = await client.messages.create({ /* ... */ });
    return { text: r.content[0].text,
             usage: { in: r.usage.input_tokens, out: r.usage.output_tokens,
                      cache_write: r.usage.cache_creation_input_tokens,
                      cache_read: r.usage.cache_read_input_tokens } };
  });

// meter.log это журнал, его и читает report.mjs
```

## Файлы

| | |
|---|---|
| `prices.json` | цены за миллион токенов, с датой |
| `meter.mjs` | счётчик, ключ кэша, стоимость вызова |
| `replay.mjs` | синтетический поток: три прогона по одному списку |
| `report.mjs` | куда ушли деньги и что даст каждая правка |

## Границы

Цены надо обновлять руками. Совет про более дешёвую модель это оценка
экономии, а не обещание качества: перевести половину потока на неё
можно только после замера на своём эталоне, иначе экономия превращается
в тихую потерю точности. Кэш здесь в памяти процесса и живёт один
прогон; общий кэш между запусками это отдельная задача с инвалидацией.
